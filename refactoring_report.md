# Отчёт по рефакторингу

## Что изменилось

За основу взяты лабораторная работа `InnopolisBigData6_1full.ipynb` и вариант с восстановлением признаков `InnopolisBigData6_1-2.ipynb`. Этапы перенесены из ячеек Colab в `pipeline.py`. Команда `python pipeline.py --config config.json` запускает весь конвейер.

| Функция | Ответственность |
| --- | --- |
| `load_data` | Читает готовый Parquet или вызывает `build_features`, приводит метки к 0/1 и объединяет таблицы по ключу абонента с проверкой один к одному. |
| `preprocess` | Выбирает числовые столбцы, заполняет пропуски нулями и выполняет два стратифицированных разбиения. Обучает StandardScaler только на train. |
| `train_model` | Обучает Random Forest на train с параметрами из конфига и пишет длительность в журнал. |
| `evaluate` | Считает ROC-AUC по вероятностям, а F1, precision и recall по ответам при заданном пороге. Метрики рассчитываются отдельно для validation и test. |

В `config.json` вынесены пути к данным, даты среза и разделов CDR, доли выборок, seed, гиперпараметры Random Forest, порог классификации, каталог и имена выходных файлов, уровень и формат логирования. Этапы и ошибки видны в консоли и в `pipeline.log`.

## Идемпотентность

Конвейер вычисляет SHA-256 от конфигурации, содержимого используемых входов, кода и версий среды. Если отпечаток совпадает с `manifest.json` и контрольные суммы всех четырёх выходных файлов верны, обучение пропускается. При изменении входов или повреждении артефакта конвейер пересчитывает набор с теми же именами файлов. Журнал дополняется при каждом запуске.

Блокировка каталога результатов не даёт двум процессам конвейера публиковать файлы одновременно. Новые файлы сначала полностью записываются во временный каталог, затем заменяются по одному. Манифест публикуется последним. Если процесс прервётся между заменами, несовпадение хешей обнаружится на следующем запуске и набор будет пересоздан.

## Сложности

- В архиве генератора есть метки и сырой слой, поэтому добавлен расчёт четырёх признаков из CDR по логике прошлой работы. Используются активные абоненты из снимка и события до среза. Для одной даты раздел поздней поставки имеет приоритет.
- В лабораторной работе встречаются разные имена целевого столбца, а CSV генератора использует логические значения. Загрузка приводит эти варианты к единому столбцу `churn` и удаляет из признаков известные поля разметки, включая `churn_day_index`.
- Первый запуск контейнера обнаружил вложенный список разделов в пути восстановления из CDR. Снимок и разделы теперь передаются одной последовательностью путей для расчёта хешей и загрузки.

## Проверка

- Собран образ `bda-churn:local` на базе Python 3.12. В контейнере проверены оба маршрута на учебных данных. Первый использовал готовый Parquet из прошлой работы. Второй восстановил признаки из 47 разделов CDR и снимка абонентов.
- Оба маршрута дали 179 396 строк и четыре признака. Размеры train, validation и test составили 107 637, 35 879 и 35 880 строк соответственно.
- Повторный запуск с CDR пропустил обучение. У модели, скейлера, списка признаков, метрик и манифеста сохранились файловые идентификаторы, размеры и время изменения.
- В контейнере сверены SHA-256 четырёх артефактов по манифесту. Сохранённые модель и скейлер загрузились и выдали вероятности для 100 строк.
- Локальный запуск на macOS с готовым Parquet также завершился успешно. Для проверки из каталога BDA образ собран повторно, а контейнер подтвердил актуальность сохранённых артефактов.

На тестовой выборке оба маршрута дали ROC-AUC **0.5497**, F1 **0.0107**, precision **0.0058** и recall **0.0714**. Эти метрики относятся к проверенному набору из четырёх признаков CDR. Низкие значения F1 и recall отражают ограниченное качество модели на этом наборе.
